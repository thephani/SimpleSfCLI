🚀 Simple SF CLI

Lightweight Salesforce SFDX Delta Deployment CLI via Metadata API — No Salesforce CLI Required

simple-sf-cli v2.7.8 · Node.js >=18.0.0 · MIT License

Why Choose Simple SF CLI?

No Salesforce CLI Required

Deploy directly via the Salesforce Metadata API (v60.0) without installing heavy CLI toolchains.

Zero Installation Overhead

Run directly with npx simple-sf-cli or install globally with just 3 runtime dependencies.

PR-Aware Delta & Destructive Changes

Auto-detects PR base/target branches in GitHub Actions & Bitbucket Pipelines and packages additions, updates, and post-deployment deletions (destructiveChangesPost.xml) in one archive.

Quick Deploy & Token Export

Instant quick-deploy for validated deployment IDs and secure auth:token JWT export with 0600 file permissions.

.forceignore & Type Filtering

Honors project .forceignore path rules (including inside LWC bundles) and comma- or space-separated --exclude metadata types.

Version 2.7.8 Highlights

Requires Node.js >=18.0.0, supports SANDBOX/SBX and PRODUCTION/PROD aliases, and enforces strict nonzero exit codes on failed or partial deployments.

Documentation

1. Standard / Delta Deployment (Zero Installation)

npx simple-sf-cli \
  --username "$SF_USERNAME" \
  --clientId "$SF_CLIENT_ID" \
  --privateKey ./server.key \
  --source force-app/main/default \
  --exclude Profile,NamedCredential \
  --validateOnly \
  --env PRODUCTION

2. Quick Deploy (Instant Validated Deployment)

npx simple-sf-cli quick-deploy \
  --username "$SF_USERNAME" \
  --clientId "$SF_CLIENT_ID" \
  --privateKey ./server.key \
  --quickDeployId "0Af30000000xyz" \
  --env PRODUCTION

3. Export JWT Access Token (auth:token)

Export a short-lived Salesforce bearer token and instance URL to a protected 0600 JSON file or stdout (--json):

npx simple-sf-cli auth:token \
  --username "$SF_USERNAME" \
  --clientId "$SF_CLIENT_ID" \
  --privateKey ./server.key \
  --env SANDBOX \
  --output .simpleSfCli_auth.json

4. Global Installation

npm install -g simple-sf-cli

PR Branch Auto-Detection

In GitHub Actions and Bitbucket Pipelines, simple-sf-cli automatically resolves pull request base and target branches from CI environment variables before falling back to the remote default branch or HEAD~1...HEAD. You can also pass explicit refs with --baseBranch and --targetBranch.

Destructive Changes (destructiveChangesPost.xml)

Mixed additions/updates and deletions—as well as deletion-only deltas—are packaged into a single deploy.zip containing root package.xml and destructiveChangesPost.xml manifests so deletions run after additions and updates. Partial LWC file deletions redeploy the surviving bundle rather than deleting the entire component.

.forceignore & Metadata Exclusions

Add a project-level .forceignore file to exclude specific files or directories before packaging (relative to project root or --source):

profiles/**
namedCredentials/**
labels/CustomLabels.labels-meta.xml

Use --exclude Profile,CustomField (or space-separated --exclude Profile CustomField) to skip entire metadata types from both package.xml and destructiveChangesPost.xml.

Command / Option Description Example / Default
-u, --username* Salesforce username user@example.com
-c, --clientId* Connected App Consumer Key (Client ID) 3MVG9XXXXXXXXX
-k, --privateKey* Path to RSA private key file for JWT auth ./keys/private.key
-e, --env Target environment (SANDBOX/SBX or PRODUCTION/PROD) SANDBOX (default)
-s, --source Path to the SFDX source directory force-app/main/default
-b, --baseBranch Base git ref for delta comparison (auto-detected in PR CI) HEAD~1
-r, --targetBranch Target git ref for delta comparison (auto-detected in PR CI) HEAD
-v, --validateOnly Validate package (including destructiveChangesPost.xml) without deploying false
-x, --exclude Comma- or space-separated metadata types to exclude (use .forceignore for paths) Profile,NamedCredential
-t, --testLevel Test level (forced to RunLocalTests in PRODUCTION) NoTestRun, RunLocalTests, RunAllTestsInOrg, RunSpecifiedTests
quick-deploy -q, --quickDeployId* Quick-deploy a previously validated deployment ID 0Af30000000xyz
auth:token --json Print JWT access token and instance URL as JSON to stdout --json
auth:token -o, --output Write JWT auth payload to a local file with 0600 permissions .simpleSfCli_auth.json
-V, --version Output the current CLI version 2.7.8

CI/CD Pipeline Configuration

GitHub Actions Configuration

name: SimpleSfCli CI

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  deploy:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Validate or Deploy Delta to Salesforce
        run: |
          npx simple-sf-cli \
            --source "${{ secrets.SOURCE }}" \
            --exclude "${{ secrets.EXCLUDE }}" \
            --clientId "${{ secrets.CLIENT_ID }}" \
            --privateKey "${{ secrets.PRIVATE_KEY }}" \
            --username "${{ secrets.USER_NAME }}" \
            --env SANDBOX \
            --validateOnly

Bitbucket Pipelines Configuration

image:

pipelines:

                --validateOnly
